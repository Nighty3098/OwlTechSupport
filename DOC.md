# Бот тех поддержки для проекта owl: https://owl-tech.vercel.app/

## Стек:

- python 3.14+
- aiogram
- sqlalchemy
- docker 
- docker compose
- postgresql

## Структура БД:

bugs:

content, attachemts ( тут храним файлы, которые приложил юзер), reporter_username (ссылается на users.username), reporter_user_id(ссылается на users.user_id), reported_at, updated_at (когда взят в работу), completed_at, completed_by_username (ссылается на developers.username), completed_by_user_id (ссылается на developers.user_id) (названия колонок можешь оптимизировать), 

features:

content, attachemts ( тут храним файлы, которые приложил юзер), reporter_username (ссылается на users.username), reporter_user_id (ссылается на users.user_id), reported_at, updated_at (когда взят в работу), completed_at, completed_by_username (ссылается на developers.username), completed_by_user_id (ссылается на developers.user_id) (названия колонок можешь оптимизировать)

users:

username, user_id, started_at (когда юзер запустил бота первый раз), reports (храним количество репортов от юзера), features (храним количество фич от пользователя).  

developers:

username, user_id, bugs (количество закрытых багов), features (количество закрытых фич), added_by_username (юзернейм того, кто добавил разраба), added_by_user_id (id того, кто добавил разраба), added_at (время добавление разраба)

## Функционал:

/start - запуск бота.
При первом запуске мы выводим приветственное сообщение и 6 кнопки с языками и флагами стран в 2 колонки: Русский, Английский, Японксий, Китайский, Испанский, Немецкий.
После того, как юзер выберет язык все последующие сообщения будут только на этом языке. Все тексты сообщений мы храним в json файлах: locale_ru.json и т.д.

Для после того как человек выбал язык, мы очищаем сообщение и убираем его кнопки.
Дальше пишем новый текст в нужной локали.
- Для юзера: Привет, это бот техподдержки и т.д. + Кнопки: баг репорт, предложить фичу, связаться с разработчиком.
- Для админа (разраба г): Добро пожаловать, у нас ... новых тикетов + Кнопки: Тикеты, команда.

Логика кнопок для юзера:
- человек кликает на кнопку -> ему отправляется новое сообщение с просьбюой описать проблему или предложить фичу и приложить сообщения или файлы. (Бот должен уметь работать с файлами и картинками, которые отправляет юзер). Данные соханяем в БД.
- отправляем сообщение юзеру что заявка отправлена успешно.

Логика кнопок для админа и разработчиков:
- админ (разраб) тыкает на кнопку (команда): сообщение + 3 кнопки: список команды, добавить участника, удалить участника.

- админ кликает на кнопку (добавить участника) -> бот запрашивает у него юзернейм или юзер ид или просит переслать сообщение от человека. После того как мы получаем хоть одни из нужных данных, по ним мы получаем остальные (username или user_id). После этого записываем разраба в developers

- админ (разраб) кликает на кнопку (удалить участника) -> бот запрашивает у него юзернейм или юзер ид или просит переслать сообщение от человека. После того как мы получаем хоть одни из нужных данных, по ним мы удаляем из БД (developers) нужную запись.

- админ (разраб) тыкает на кнопку (список команды) -> Бот присылет большое сообщение (или несколько сообщений если не входит одно). В сообщении через одну пропущенную строчку пишем данные: @username\nuser_id\nAdded by@added_by_username\nAdded at: added_at\n\n\n.

Логика работы с тикетами:

- Как только юзер отправляет тикет мы формируем сообщение со всеми полями из БД, к сообщению прикрепляем файлы из бд (которые прикрепил пользователь) + кнопка: изменить статус.

- Когда разраб тыкает на кнопку изменить статус мы запрашиваем у него в диалоге новый статус: Not started | In Dev | Completed. После этого заполняем все нужные поля в базе данных.

## Требования к проекту:

- Данные хранятся в .env и docker берет переменные окружения только из .env.
- Бот должен поддерживать как работу только с чатом, так и с топиком внутри чата. Например вот группа: 3800802201, вот топик: https://t.me/c/3800802201/37. Должно поддерживаться в .env
- Должна быть поддержка proxy внутри docker контейнера в формате socks5 или https, то есть мы в .env прописываем proxy в любом формате, в коде валидируем его и используем.
- Порты и нужные данные для БД задаются через .env
- Покрытие автотестами pytest
- CI с автотестами
- requirements файл.
- Автоматическая генерация THIRDPARTY NOTICE как тут: /home/nighty/Dev/OWL_PROJECT/owl_backend внутри CI.
